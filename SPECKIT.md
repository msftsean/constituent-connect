# GitHub Spec Kit Workflow

This repository was shaped in the GitHub Spec Kit order and must continue to evolve in that order.

1. Constitution: `.specify/memory/constitution.md`
2. Specify: `specs/001-constituent-connect/spec.md`
3. Clarify: `specs/001-constituent-connect/clarifications.md`
4. Plan: `specs/001-constituent-connect/plan.md`
5. Analyze: `specs/001-constituent-connect/analysis.md`
6. Tasks: `specs/001-constituent-connect/tasks.md`
7. Implement: source, tests, infrastructure, labs, and runbooks

## Change rule

A scope or policy change begins by updating the constitution or specification. Plans and tasks must be regenerated or reconciled before implementation changes.

## All Clear reference rule

All Clear is the reference for delivery patterns: canonical vocabulary, bounded agents, deterministic decision stages, local-first startup, progressive labs, observability, eval gates, safety assets, participant guidance, coach guidance, and deployment evidence. Constituent Connect retains its own non-emergency contact-center domain and safety boundary.
